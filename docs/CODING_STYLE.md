# 코딩 규약

기준 시점 : 2026-09-13

dx-render-dojo 의 C++ 코드 규약입니다. 코드를 쓰다가 걸리는 주제의 절만 찾아 읽으면 됩니다. 규약을 바꿀 때는 이 문서를 고칩니다.

이 문서에서 "원문"은 Rastertek DirectX 11 튜토리얼의 코드를 가리킵니다.

서식은 `.clang-format`, 네이밍은 `.clang-tidy` 로 검사합니다. 도구가 잡지 못하는 항목은 사람이 지킵니다.

## 1. 추상화

구조는 기법이 요구할 때 생깁니다. 미리 만드는 것은 도구와 뼈대뿐입니다.

- 현재 튜토리얼이 요구하지 않는 추상화는 만들지 않음. 중복은 3번째에서 뽑음
- 예외 : 아래 둘을 모두 만족하면 미리 넣음
  - 확실성 : 교재 진행이나 자체 렌더러가 요구함. "쓸 것 같다" 는 해당 없음
  - 비용 역전 : 나중에 넣는 비용이 지금보다 크게 높음. 태그 diff 가 그대로 교재 코드가 되므로 구조 변경은 뒤 편일수록 비쌈
- 예외로 미리 넣은 것 : 공통 도구(로그, 체크 매크로, 싱글톤 틀), 프레임 구조(`Update`/`Render` 분리)
- 예외가 아닌 것 : 백엔드 추상화(RHI), 렌더 그래프, 셰이더 공통 베이스. 요구되는 편에서 만듦

## 2. 소유

- COM 객체 : `ComPtr<T>`
- 내 객체 : 값 멤버가 기본. 다형성이 필요할 때, 다시 만들어야 할 때, 생성을 늦춰야 할 때만 `std::unique_ptr<T>`
- `shared_ptr` : 쓰지 않음
- raw 포인터·참조 : 빌리는 매개변수에만
- `new` / `delete` : 직접 호출 금지

해제는 값 멤버의 소멸자와 `ComPtr`·`std::unique_ptr` 가 맡습니다. 그래서 `Shutdown` 계열 함수와 `SafeRelease` 는 쓰지 않습니다.
창·디스플레이 설정처럼 스마트 포인터가 맡지 못하는 자원은 소멸자에서 돌려놓습니다.

**싱글톤 수명**

- `Get()` 은 인스턴스가 없으면 만듦. 대부분의 싱글톤은 이것만으로 충분함
- 생성 비용이 크거나 생성 시점을 잡아야 하면 `Prepare()` 로 앞당김. `FSystem` 이 여기에 해당함
- 해제 시점이 중요한 싱글톤만 `Release()` 를 부름. 그 밖은 프로세스 종료에 맡김
- `Shutdown` 계열 은퇴의 예외는 이 `Prepare`·`Release` 둘뿐임

## 3. 초기화

- 멤버 : 헤더에서 기본 초기화
- 생성자·소멸자 : 필요할 때만. 본문이 빈 생성자·소멸자는 쓰지 않음
- 복사 : `= delete`. 이때 기본 생성자가 사라지므로 `= default` 로 한 줄 적음. 베이스가 이미 막았으면 파생에는 적지 않음
- 실패할 수 있는 초기화만 `bool Initialize()`
- `Initialize` 는 직접 일함. `InitializeShader` 같은 내부 위임 함수 금지

## 4. 에러

- 실패 검사 : `CHECK_RETURN(expr, false)` 로 통일
- `if (FAILED(hr)) return false;` : 금지
- `CHECK_RETURN` 은 `HRESULT`·`bool`·포인터만 받음. 그 밖의 반환값은 성공 조건을 비교식으로 적음 (`RegisterClassExW(...) != 0`)

`BOOL`·`ATOM` 을 받는 오버로드는 두지 않습니다. `int` 오버로드가 생기면 0 이 성공인 `errno_t`(`fopen_s` 등)의 판정이 뒤집히고, `short`·범위 없는 `enum` 을 넘겼을 때 나던 컴파일 에러도 사라집니다.

## 5. 문자열

- 경로 : `std::filesystem::path` 또는 `const wchar_t*`
- 보관 : `std::wstring`
- const 가 아닌 `char*` : 금지

## 6. 네이밍

언리얼 컨벤션을 전면 채택합니다.

| 대상 | 접두 |
|---|---|
| 클래스·구조체 | `F` |
| 인터페이스 (순수 가상 함수만 있는 클래스) | `I` |
| 추상 클래스 | `A` |
| 템플릿 | `T` |
| enum | `E` |
| bool 변수 | `b` |

- 멤버·로컬·매개변수·함수·파일 : 모두 PascalCase
- 파일 이름 : 접두까지 클래스 이름과 같게 (`FModel` → `FModel.h`, `FModel.cpp`)
- 원문의 `Class` 접미사 : 떼고 접두를 붙임 (`ModelClass` → `FModel`)

`.clang-tidy` 가 잡지 못해 사람이 확인하는 것

- 파일 이름
- `T` 는 템플릿에만. 도구는 `T` 로 시작하는 클래스 이름을 검사하지 않음
- `I` 는 순수 가상 함수만 있는 클래스에만. 도구는 추상 클래스 중 `I` 로 시작하는 이름을 검사하지 않음
- bool 변수의 `b`. 도구는 `b` 로 시작하는 이름을 검사하지 않을 뿐, 그 변수가 bool 인지는 보지 않음
- `!` 대신 `== false` (8절). 도구가 검사하지 않음

## 7. 헤더

- `#pragma once` 사용
- 매개변수 이름 : 항상 표기
- 한 줄 게터 : 인라인 `const`
- `using namespace` : 헤더에서 금지
- 전역 상수 : 두지 않음. 한 함수만 쓰면 그 함수 안의 `constexpr`, 여러 함수가 쓰면 클래스의 `static constexpr` 나 멤버로
- static 멤버 : 클래스 선언과 `.cpp` 정의 모두 맨 위

## 8. 서식

- 중괄호 : Allman
- 들여쓰기 : 탭
- 줄 길이 : 120자 상한
- 부정 : `== false` 로 적음. `!` 는 삼항 연산자 안처럼 줄 길이가 빠듯할 때만
- void 함수 끝 `return;` : 쓰지 않음
- 블록 뒤 빈 줄 2개 : 두지 않음
- 120자를 넘는 인자·매개변수 목록 : 한 줄에 하나씩
- 접근 지정자 : 들여쓰지 않음 (`public:` 을 `class` 와 같은 열에)
- 네임스페이스 : 안쪽을 들여씀 (`NamespaceIndentation: All`)
- 포인터·참조 : `*` 와 `&` 를 타입에 붙임 (`const wchar_t* Name`, `const FWindow& Window`)
- 그 밖의 서식 : Microsoft 스타일 기본값

120자 상한은 학습 노트 때문입니다. 노트의 코드 블록은 가로 스크롤 대신 자동 줄바꿈되므로 긴 줄은 읽기가 깨집니다.

## 9. 기각안과 변경 이력

**기각안**

- `m_camel` : 번거로움
- `_Upper` : 예약어
- `CHECK_RETURN` 의 `BOOL`·`ATOM` 오버로드 : 4절 참고

**언리얼식 네이밍 채택 (2026-09-13)**

2026-08-23 에는 "멤버/로컬 구분이 약함" 을 이유로 기각했습니다. 2026-09-13 에 아래 이유로 채택했고, 구분이 약한 문제는 감수합니다.

- 스터디원이 언리얼 트랙 출신이라 접두 어휘가 독자에게 익숙함
- 회사 UE5 코드와 표기가 같아져 손에 익은 대로 쓸 수 있음

**이 문서로 옮기면서 정한 것 (2026-09-13)**

- 파일 이름에 접두 포함
- 추상 클래스 접두 `A` 추가. 인터페이스 `I` 는 순수 가상 함수만 있는 클래스로 한정
- `Shutdown` 계열도 `SafeRelease` 와 함께 은퇴
- 원문 이름과 새 이름의 대응 표는 두지 않음. 클래스를 분리하면 원문과 대응되지 않는 경우가 있기 때문. 필요해지면 참고용으로 이 문서 위나 아래에 추가

**02편을 쓰면서 정한 것 (2026-09-13)**

- 생성자·소멸자는 필요할 때만. 창처럼 스마트 포인터가 맡지 못하는 자원은 소멸자에서 정리
- 전역 상수 금지. 쓰는 클래스의 `static constexpr` 나 멤버로
- `CHECK_RETURN` 은 `HRESULT`·`bool`·포인터만. 그 밖의 반환값은 비교식
- static 멤버는 클래스 맨 위
- 접근 지정자는 들여쓰지 않음

**02편 설계 수정 (2026-09-20)**

근거는 2026-09-20 조사 세션입니다. DirectXTK 템플릿·hw3d·learnd3d11·Godot·Unreal 을 대조했습니다.

- 소유는 값 멤버가 기본. 참고한 코드베이스가 모두 값 멤버를 기본으로 쓰고, `unique_ptr` 는 다형성·재생성·지연 생성일 때만 씁니다
- 1절 추상화에 예외 두 조건(확실성·비용 역전)을 넣었습니다. 태그 diff 가 그대로 교재 코드가 되어, 구조를 뒤 편에서 바꾸는 비용이 크기 때문입니다
- 3절 복사 금지에 "베이스가 이미 막았으면 파생에는 적지 않음" 을 넣었습니다. 베이스가 복사를 `= delete` 하면 파생의 복사는 컴파일러가 자동으로 delete 하고, 파생이 생성자를 선언하지 않았으므로 기본 생성자도 그대로 남습니다. `TSingleton` 을 상속하는 `FSystem`·`FLog` 가 여기에 해당합니다

**02편 코드 리뷰 (2026-09-20)**

- 2절에 싱글톤 수명 항목을 넣었습니다. 그 전에는 `wWinMain` 이 객체를 값으로 들고 `TSingleton` 은 포인터만 등록했는데, 싱글톤이라는 이름과 "밖에서 만들고 소유한다" 는 실체가 어긋났습니다. 이제 `TSingleton` 이 `static std::unique_ptr` 로 소유합니다
- 8절에 부정 표기를 넣었습니다. `!` 는 한 글자라 훑어 읽을 때 놓치기 쉽습니다
- 7절 전역 상수에 "한 함수만 쓰면 그 함수 안의 `constexpr`" 을 앞에 넣었습니다. 범위가 좁은 쪽을 먼저 적은 것이고 취지는 그대로입니다
