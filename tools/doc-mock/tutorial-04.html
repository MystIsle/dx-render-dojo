버퍼·셰이더·HLSL

정점 버퍼와 HLSL 셰이더로 초록 삼각형 하나를 그려요. 정점을 GPU 버퍼에 올리고, 셰이더가 화면 위치와 색을 정하고, 그리기 전에 파이프라인에 그림을 받을 곳을 묶는 순서를 처음부터 끝까지 따라가요.

  1. DirectXMath 를 들인다

    04편부터 벡터와 행렬 계산에 DirectXMath 를 써요. Windows SDK 에도 들어 있지만 맥 빌드가 쓰는 mingw 의 헤더에는 행렬 형 XMMATRIX 가 없어요. 공식 릴리스를 리포의 external/ 에 넣고 Visual Studio 빌드와 mingw 빌드가 같은 사본을 써요.

    GitHub 의 microsoft/DirectXMath 에서 릴리스 jun2026 의 소스 zip 을 받아요. 압축을 풀어 Inc 폴더의 파일 10개를 external/DirectXMath/Inc 로, LICENSE 를 external/DirectXMath 로 옮겨요. 포함 경로는 8단계에서 빌드에 더해요.

    줄 단위 풀이
    • XMVerifyCPUSupport() DirectXMath 는 CPU 의 SIMD 명령으로 계산함. 이 CPU 가 그 명령을 지원하는지 먼저 확인하고, 지원하지 않으면 곧바로 멈춤
    • #include "Utility/Check.h" CHECK_FATAL 을 쓰려고 넣음
    원문과 비교

    원문은 Windows SDK 의 directxmath.h 를 쓰고 CPU 확인은 하지 않아요.

  2. 정점과 인덱스를 버퍼에 담는다

    GPU 가 그릴 정점은 GPU 가 읽는 버퍼에 들어 있어야 해요. 삼각형 하나라도 C++ 배열을 그대로 넘기지 않고, 정점 버퍼와 인덱스 버퍼를 만들어 배열 내용을 복사해요.

    D3D 개념 · 버퍼와 입력 조립기
    • 버퍼(ID3D11Buffer) : GPU 가 읽는 메모리 덩어리. 정점·인덱스·상수 버퍼가 모두 같은 형이고, 만들 때 BindFlags 로 쓰임을 정함
    • 정점 버퍼 : 정점 구조체를 늘어놓은 버퍼
    • 인덱스 버퍼 : 정점 번호를 늘어놓은 버퍼. 세 개가 삼각형 하나. 여러 삼각형이 한 정점을 나눠 쓸 수 있음
    • 입력 조립기(IA, Input Assembler) : 파이프라인의 첫 단계. 묶인 버퍼에서 정점을 읽어 도형으로 모음
    • 토폴로지 : 정점 목록을 어떤 도형으로 읽을지. D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST 는 세 개씩 삼각형 하나
    줄 단위 풀이
    • struct FVertex 정점 하나. 위치 XMFLOAT3(12바이트) 다음에 색 XMFLOAT4(16바이트). 4단계의 입력 레이아웃이 이 배치를 그대로 적음
    • void Render(ID3D11DeviceContext* Context) const; 7단계
    • UINT GetIndexCount() 그리기 명령에 넘길 인덱스 개수

    정점은 왼쪽 아래, 가운데 위, 오른쪽 아래 순서로 적어요. 카메라에서 보면 시계 방향이에요. 기본 래스터라이저 상태는 시계 방향으로 도는 삼각형을 앞면으로 보고 뒷면은 그리지 않아요.

    줄 단위 풀이
    • constexpr std::array<FVertex, 3> Vertices 좌표는 z = 0 평면의 -1~1. 세 정점 모두 초록(0, 1, 0, 1)
    • ByteWidth = sizeof(Vertices) 버퍼 크기(바이트). 정점 28바이트 × 3
    • D3D11_USAGE_IMMUTABLE 만들 때 채운 뒤 바뀌지 않는 버퍼. GPU 는 읽기만 하고 CPU 는 읽지도 쓰지도 못함. 만들 때 데이터를 반드시 넘겨야 함
    • D3D11_BIND_VERTEX_BUFFER 입력 조립기에 정점 버퍼로 묶을 버퍼
    • VertexData.pSysMem = Vertices.data() 처음 채울 데이터. CreateBuffer 가 복사하므로 함수가 끝나 배열이 사라져도 됨
    • D3D11_BIND_INDEX_BUFFER 인덱스 버퍼로 묶을 버퍼
    원문과 비교

    원문은 new 로 정점·인덱스 배열을 만들어 채우고 버퍼를 만든 뒤 delete 해요. 버퍼는 D3D11_USAGE_DEFAULT 예요. 이 교재는 함수 안의 constexpr 배열을 쓰고, 한 번 채우고 바꾸지 않는 버퍼라 D3D11_USAGE_IMMUTABLE 로 만들어요.

    원문의 인덱스 형 unsigned long 은 Windows 에서 32비트예요. 크기를 이름에 드러내려고 std::uint32_t 로 적었어요.

    언리얼로 치면

    같은 점 · 정점 버퍼(FVertexBuffer)와 인덱스 버퍼(FIndexBuffer)가 같은 RHI 버퍼 형 FBufferRHIRef 를 가져요. D3D11 이 둘을 모두 ID3D11Buffer 로 만드는 것과 같아요.

    다른 점 · 둘 다 FRenderResource 를 상속하고 GPU 버퍼는 InitRHI 에서 만들어요.

    스스로 설명해 보기

    삼각형 하나는 인덱스 버퍼 없이 정점 버퍼만으로도 그릴 수 있어요. 사각형을 삼각형 두 개로 그릴 때 인덱스 버퍼가 있으면 정점 버퍼에서 무엇이 줄어드는지 말해 보세요.

  3. 정점 셰이더와 픽셀 셰이더를 쓴다

    셰이더는 GPU 에서 도는 작은 프로그램이에요. 정점 셰이더는 정점마다 한 번 돌아 화면 위치를 정하고, 픽셀 셰이더는 삼각형이 덮는 픽셀마다 한 번 돌아 색을 정해요. 둘 다 HLSL 로 써요.

    D3D 개념 · 시맨틱
    • 시맨틱 : 변수 뒤에 붙는 : POSITION 같은 이름. 파이프라인 단계 사이에서 값을 이 이름으로 짝지음
    • POSITION·COLOR 정점 버퍼에서 읽는 값. 4단계 입력 레이아웃의 이름과 같아야 함
    • SV_POSITION 정점 셰이더가 내보내는 위치. SV_ 는 파이프라인이 직접 쓰는 시스템 값이라는 표시
    • SV_TARGET 픽셀 셰이더의 출력. 0번 렌더 타깃에 씀

    두 파일을 Source/Shaders 에 새로 만들어요. 인코딩은 BOM 없는 UTF-8 이어야 해요. BOM 이 있으면 컴파일이 첫 글자에서 실패해요(흔한 실수 3번).

    줄 단위 풀이
    • cbuffer MatrixBuffer : register(b0) C++ 이 채워 넣는 값 묶음. 그리기 한 번 동안 모든 정점이 같은 값을 읽음. b0 은 상수 버퍼 0번 슬롯. 5단계
    • matrix 4×4 float 행렬
    • float3 Position : POSITION 정점 버퍼의 XMFLOAT3 를 받음
    • mul(float4(Input.Position, 1.0f), World) 위치에 w = 1 을 붙여 네 성분으로 만든 뒤 월드 행렬을 곱함. 이어서 뷰, 투영 순서
    • Output.Color = Input.Color; 색은 그대로 넘김

    픽셀 셰이더가 받는 Input.Color 는 정점 셰이더가 내보낸 색이에요. 래스터라이저가 삼각형 안쪽 픽셀마다 세 정점의 값을 섞어서 넘겨요.

    원문과 비교

    원문은 위치를 float4 로 받고 w 를 1 로 덮어써요. 정점 버퍼의 위치는 세 성분이라 이 교재는 float3 로 받아 w 를 붙여요.

    원문은 cbuffer 에 슬롯을 적지 않아 컴파일러가 정해요. 이 교재는 register(b0) 으로 C++ 이 묶는 슬롯 번호와 맞춰 둬요. 구조체 이름은 VertexInputType 이 FVertexInput, PixelInputType 이 FPixelInput 이에요.

  4. 셰이더를 컴파일하고 입력 레이아웃을 만든다

    HLSL 파일은 실행 중에 D3DCompileFromFile 로 컴파일해요. 컴파일 결과인 바이트코드로 셰이더 객체를 만들고, 정점 셰이더의 바이트코드로 입력 레이아웃도 만들어요.

    D3D 개념 · 바이트코드와 입력 레이아웃
    • 바이트코드(ID3DBlob) : 컴파일된 셰이더. 드라이버가 이것을 GPU 명령으로 바꿈
    • vs_5_0·ps_5_0 셰이더 모델 5.0 의 정점 셰이더와 픽셀 셰이더로 컴파일하라는 대상 이름
    • 입력 레이아웃(ID3D11InputLayout) : 정점 버퍼의 바이트를 정점 셰이더 입력의 어느 변수로 읽을지 적은 표. 시맨틱 이름으로 짝지음
    줄 단위 풀이
    • struct FMatrixBuffer 5단계
    • void Render(...) const; 7단계
    • const DirectX::XMMATRIX& World 행렬은 참조로 받음. 헤더에서는 using namespace 를 쓰지 않아 DirectX:: 를 붙임

    CompileShader 는 파일 하나를 컴파일해 바이트코드를 돌려줘요. 실패하면 경로와 컴파일러가 돌려준 오류 문자열을 로그로 남긴 뒤 CHECK_FATAL 로 멈춰요. 오류 문자열에는 파일 이름과 줄·열 번호가 들어 있어요.

    줄 단위 풀이
    • namespace { ... } 이름 없는 네임스페이스. CompileShader 는 이 파일에서만 보임
    • D3DCOMPILE_ENABLE_STRICTNESS 옛 문법을 오류로 봄
    • D3DCOMPILE_DEBUG | D3DCOMPILE_SKIP_OPTIMIZATION 디버그 빌드만. RenderDoc 이나 PIX 같은 그래픽 디버거에서 HLSL 을 줄 단위로 따라갈 수 있음

  5. 카메라로 뷰·투영 행렬을 만든다

    정점 셰이더는 정점 위치에 월드·뷰·투영 행렬을 차례로 곱해요. 월드 행렬은 모델을 세상 안에 놓고, 뷰 행렬은 세상을 카메라 기준으로 옮기고, 투영 행렬은 원근을 주어 화면에 맞춰요.

    D3D 개념 · 좌표 공간과 상수 버퍼
    • 좌표 공간 : 모델 공간 → 월드 공간 → 뷰 공간 → 투영 공간. 행렬 하나가 한 칸씩 옮김
    • 왼손 좌표계 : +x 오른쪽, +y 위, +z 화면 안쪽. DirectXMath 에서 이름이 LH 로 끝나는 함수가 이 기준
    • 상수 버퍼 : 그리기 한 번 동안 모든 정점이 함께 읽는 값을 담는 버퍼. D3D11_BIND_CONSTANT_BUFFER 로 만듦
    줄 단위 풀이
    • float FovAngleY = DirectX::XM_PIDIV4; 세로 시야각 45°(π/4)
    • NearZ = 0.3f, FarZ = 1000.0f 카메라에서 이 거리 사이에 있는 것만 그림
    • XMMatrixLookToLH(Eye, Forward, Up) 카메라 위치에서 +z 방향을 보는 뷰 행렬. 위쪽은 +y
    • XMMatrixPerspectiveFovLH(FovAngleY, AspectRatio, NearZ, FarZ) 세로 시야각과 종횡비(가로÷세로)로 가로 시야를 정함

    GetProjectionMatrix 는 종횡비를 인자로 받아요. 7단계의 FApplication::Render 가 매 프레임 지금 뷰포트의 가로÷세로를 넘겨서, 창 비율이 바뀌면 투영 행렬도 그 프레임부터 바뀌어요.

    카메라는 z = -5 에서 원점을 봐요. 시야각 45° 로 거리 5 를 보면 화면 세로에 2 × 5 × tan 22.5° ≈ 4.14 만큼 담겨서 높이 2 인 삼각형은 창 높이의 약 0.48 을 차지해요. 창 높이 600 픽셀이면 약 290 픽셀이에요.

    행렬 셋은 상수 버퍼에 담아 넘겨요. FColorShader::Initialize 끝에서 상수 버퍼를 만들어요.

    줄 단위 풀이
    • static_assert(sizeof(FMatrixBuffer) % 16 == 0); 상수 버퍼 크기는 16바이트의 배수여야 함. 행렬 셋은 192바이트
    • D3D11_USAGE_DYNAMIC CPU 가 자주 새로 쓰는 버퍼. 행렬은 매 프레임 바뀜
    • D3D11_CPU_ACCESS_WRITE CPU 가 쓸 수 있게 함. DYNAMIC 과 짝
    • nullptr 처음 채울 데이터 없음. 그릴 때마다 채움
    원문과 비교

    원문은 투영·월드·직교 행렬을 D3DClass 가 초기화 때 만들어 두고 게터로 내줘요. 저는 투영 행렬을 카메라로 옮겼어요. 시야각과 가까운 면·먼 면은 카메라 렌즈의 값이고, 창 비율은 매 프레임 받으면 크기가 바뀔 때 따로 맞출 값이 없어요. 원문의 SCREEN_NEAR·SCREEN_DEPTH 가 NearZ·FarZ 예요.

    원문 CameraClass 의 회전과 GetPosition·GetRotation 은 이 편에서 쓰는 곳이 없어 넣지 않았어요.

    언리얼로 치면

    같은 점 · 시야각은 카메라 컴포넌트(UCameraComponent::FieldOfView)가 갖고, 투영 행렬은 FMinimalViewInfo::CalculateProjectionMatrix 가 종횡비(AspectRatio)를 받아 만들어요.

    다른 점 · 언리얼의 시야각은 가로 기준이에요. 투영 행렬(FReversedZPerspectiveMatrix)은 가까운 면만 받아서 먼 면이 없고, 깊이를 거꾸로 저장해요.

  6. 그리기 전에 RTV 와 뷰포트를 묶는다

    삼각형을 그리려면 그림을 받을 곳과 펼칠 사각형을 파이프라인에 알려 줘야 해요. 그림을 받을 곳은 출력 병합기에 묶는 RTV 이고, 펼칠 사각형은 래스터라이저에 넣는 뷰포트예요.

    플립 모델에서는 Present 가 성공할 때마다 백 버퍼를 파이프라인에서 떼요. 초기화 때 한 번만 묶어 두면 두 번째 프레임부터는 그린 것이 버려져요. BeginScene 이 매 프레임 RTV 를 다시 묶는 이유예요. 뷰포트는 Present 가 떼지 않지만 RTV 와 짝이라 같은 자리에서 넣어요.

    D3D 개념 · 래스터라이저와 출력 병합기
    • 래스터라이저(RS) : 삼각형이 덮는 픽셀을 찾는 단계. 뷰포트로 -1~1 좌표를 창의 픽셀 좌표로 바꿈
    • 뷰포트(D3D11_VIEWPORT) : 그림을 펼칠 사각형과 깊이 범위(0~1)
    • 출력 병합기(OM) : 픽셀 셰이더가 낸 색을 렌더 타깃에 쓰는 마지막 단계. OMSetRenderTargets 로 RTV 를 묶음

    뷰포트 크기는 CreateSizeDependentResources 가 백 버퍼에서 읽어 둬요. 이 함수는 Initialize 와 Resize 가 같이 부르므로 창 크기가 바뀌거나 Alt+Enter 로 전체 화면이 돼도 뷰포트가 따라가요.

    줄 단위 풀이
    • OMSetRenderTargets(1, RenderTargetView.GetAddressOf(), nullptr) RTV 하나를 묶음. 세 번째 인자는 깊이 버퍼 뷰. 이 편에는 깊이 버퍼가 없음
    • RSSetViewports(1, &Viewport) 뷰포트 하나를 넣음
    • BackBuffer->GetDesc(&BackBufferDesc) 백 버퍼의 너비와 높이를 읽음. 창 크기를 따로 넘겨받지 않아도 됨
    • Viewport.MaxDepth = 1.0f 깊이 범위 0~1. TopLeftX·TopLeftY·MinDepth 는 헤더에서 0 으로 초기화함
    • GetDevice()·GetContext() 7단계의 FApplication 이 씀
    • GetAspectRatio() 뷰포트 너비÷높이. 투영 행렬에 넘기는 종횡비

    Resize 는 ResizeBuffers 전에 RTV 를 파이프라인에서도 떼요. 파이프라인에 묶인 RTV 도 백 버퍼를 참조해요. Present 가 이미 떼 두지만 그 규칙에 기대지 않아요.

    원문과 비교

    원문은 D3DClass::Initialize 에서 OMSetRenderTargets 와 RSSetViewports 를 한 번 불러요. 원문 스왑체인은 DXGI_SWAP_EFFECT_DISCARD 라 Present 뒤에도 묶인 채로 남아요. 원문은 깊이 스텐실 뷰도 함께 묶어요. 이 교재는 깊이 버퍼를 쓰기 시작하는 편에서 넣어요.

    언리얼로 치면

    같은 점 · D3D11 백엔드는 렌더 패스를 시작할 때(FD3D11DynamicRHI::RHIBeginRenderPass) 렌더 타깃을 묶고 지워요. 뷰포트는 RHISetViewport 가 따로 넣어요.

    다른 점 · 한 프레임에 렌더 패스가 여러 번이라 묶기도 패스마다 해요. 패스가 끝나면(RHIEndRenderPass) 렌더 타깃을 떼요.

    스스로 설명해 보기

    CreateSizeDependentResources 에서 Viewport.Width 를 백 버퍼 너비의 절반으로 바꾸면 삼각형은 창의 어디에 어떤 모양으로 그려질까요? GetAspectRatio 도 이 값을 쓴다는 점까지 넣어 말해 보세요.

  8. 새 파일을 빌드에 등록한다

    CMake 빌드는 CMakeLists.txt 에 새 파일을 적고, DirectXMath 포함 경로와 셰이더 컴파일 라이브러리 d3dcompiler 를 더해요. 셰이더 파일은 빌드 결과 옆 Shaders 폴더로 복사해요.

    줄 단위 풀이
    • SYSTEM 바깥 헤더로 표시. 그 헤더의 경고가 우리 코드의 경고와 섞이지 않음
    • d3dcompiler D3DCompileFromFile 이 든 라이브러리
    • configure_file(... COPYONLY) 설정 단계에서 파일을 복사함. 원본을 고치면 다음 빌드 때 CMake 가 다시 돌아 새로 복사함

    Visual Studio 에서는 Graphics 필터에 FCamera·FModel 의 두 파일씩을, 새 Shaders 필터에 FColorShader.h·FColorShader.cpp·Color.vs·Color.ps 를, Utility 필터에 FPaths.h·FPaths.cpp 를 기존 항목 추가로 넣어요.

    프로젝트 속성은 구성을 모든 구성으로 두고 두 곳을 고쳐요. C/C++ › 일반 › 추가 포함 디렉터리에 $(ProjectDir)external\DirectXMath\Inc 를, 링커 › 입력 › 추가 종속성에 d3dcompiler.lib 를 더해요.

    Color.vs·Color.ps 는 둘을 함께 골라 속성을 열고, 구성을 모든 구성으로 둬요. 구성 속성 › 일반 › 항목 형식을 파일 복사로 바꾸고, 파일 복사 › 일반 › 대상 디렉터리에 $(OutDir)Shaders 를 적어요. 빌드할 때마다 exe 옆 Shaders 폴더로 복사되고 셰이더만 고쳐도 다시 복사돼요. 이 조작들이 DxRenderDojo.vcxproj 와 DxRenderDojo.vcxproj.filters 를 바꿔요.
