이 편을 마치면

  • 실행800×600 검은 창이 화면 가운데에 뜨고, ESC 를 누르면 닫힙니다

따라 하기

  1. 설정과 입력 : FDisplaySettings, FInput

    원문은 FULL_SCREEN 같은 상수를 헤더의 전역에 둡니다.
    여기서는 창 크기와 전체 화면 여부를 FDisplaySettings 구조체로 묶고, 쓰는 클래스인 FSystem 의 멤버로 둡니다.

    FInput 은 키 256개의 눌림 상태를 std::array<bool, 256> 로 들고 있습니다.
    헤더에서 전부 false 로 초기화하므로 원문의 Initialize 가 필요 없습니다.

  2. 실패 검사 : CHECK_RETURN

    CHECK_RETURN(식, 반환값) 은 식이 실패면 출력 창에 위치를 남기고 바로 반환합니다.
    HRESULT·bool·포인터만 받습니다.

    0 이면 실패인 ATOM 이나 BOOL 은 성공 조건을 비교식으로 적어 넘깁니다.

  3. 누가 무엇을 들고 있나 : FSystem 선언

    FInput 과 FApplication 은 std::unique_ptr 로 들고 있어, FSystem 이 사라질 때 함께 지워집니다.
    창·창 클래스·디스플레이 설정은 스마트 포인터가 맡지 못하므로 소멸자에서 돌려놓습니다.

    FSystem 은 창에 자기 주소를 저장하므로 복사되면 안 됩니다.
    복사를 = delete 로 막고, 그러면 사라지는 기본 생성자를 = default 로 적습니다.

  4. 창 만들기와 메시지 연결 : Initialize, WndProc

    Initialize 는 이 순서로 일합니다.

    1. 입력과 앱 객체를 만듦
    2. 창 클래스를 등록하고, 메시지를 받을 함수로 WndProc 를 지정
    3. 창 위치를 화면 가운데로 계산
    4. CreateWindowExW 의 마지막 인자로 this 를 넘겨 창을 만듦
    5. 창을 보이고 커서를 숨김

    창 프로시저는 this 없이 불리므로 멤버 함수를 쓸 수 없고 static 이어야 합니다.
    그래서 CreateWindowExW 에 넘긴 this 가 WM_NCCREATE 로 돌아오면 창에 저장해 두고, 이후 메시지마다 꺼내서 HandleMessage 로 보냅니다.
    원문의 전역 포인터가 하던 일입니다.

  5. 메시지 루프와 종료 : Run, Frame, 소멸자

    Run 은 쌓인 메시지를 모두 처리한 뒤 한 프레임을 돕니다.
    WM_QUIT 이 오거나 Frame 이 false 를 돌려주면 끝납니다.

    Frame 은 ESC 가 눌렸으면 false, 아니면 FApplication::Frame 의 결과를 돌려줍니다.
    02편의 FApplication::Frame 은 늘 true 이고, 03편부터 여기서 그립니다.

    WinMain 이 끝나면 unique_ptr 가 FSystem 을 지우고, 소멸자가 커서·해상도·창·창 클래스를 돌려놓습니다.

  6. 빌드에 등록

    새 .cpp 는 DxRenderDojo.vcxproj 와 CMakeLists.txt 양쪽에 등록합니다.
    include 는 Source/ 를 기준으로 폴더까지 적습니다. 예) #include "Core/FSystem.h"

    원문이 헤더에 적던 WIN32_LEAN_AND_MEAN 은 두 빌드 설정에 넣었습니다.

흔한 실수

error C2027: 정의되지 않은 형식 'FApplication'을(를) 사용했습니다
can't delete an incomplete type

원인FSystem.h 에서 class FApplication; 전방 선언만 하고 std::unique_ptr<FApplication> 멤버를 두었습니다.
헤더의 FSystem() = default; 가 unique_ptr 소멸자를 만들어야 하는데, 그 자리에서는 FApplication 을 어떻게 지우는지 모릅니다.

해결멤버 타입의 헤더를 FSystem.h 에서 include 합니다.
생성자와 소멸자를 .cpp 에서 정의해도 풀립니다.

CHECK_RETURN(RegisterClassExW(&WindowClass), false) 에서 error C2668 : 오버로드된 함수 호출이 모호함

원인RegisterClassExW 는 ATOM 을 돌려주고 0 이면 실패입니다.
CHECK_RETURN 은 이런 정수를 HRESULT 로 잘못 판정하지 않도록 받지 않게 막아 두었습니다.

해결RegisterClassExW(&WindowClass) != 0 처럼 성공 조건을 비교식으로 적습니다.

창을 만드는 순간 WndProc 에서 크래시가 난다

원인WM_NCCREATE 보다 먼저 오는 메시지(WM_GETMINMAXINFO)가 있습니다.
그때는 아직 창에 FSystem 주소를 저장하기 전이라 꺼낸 값이 nullptr 입니다.

해결주소를 꺼내지 못했으면 DefWindowProcW 로 넘깁니다.
WndProc 의 nullptr 검사가 그 일입니다.
