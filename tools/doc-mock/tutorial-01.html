따라 하기 전에 답을 하나씩 정해 두세요. 틀려도 돼요. 정해 둔 답이 있으면 따라 하다가 그 대목에서 멈추게 돼요.

1 · DirectX 11 헤더는 어디서 올까요

DirectX 11 코드는 d3d11.h 를 include 해요. 이 헤더를 쓰려면 SDK 를 따로 받아야 할까요?

답 보기

따로 받지 않아요. d3d11.h 와 DirectXMath 는 Windows SDK 에 들어 있고, Windows SDK 는 Visual Studio 의 C++ 워크로드와 함께 설치돼요. (1단계)

2 · 빈 프로그램을 실행하면 무엇이 보일까요

이 편의 WinMain 은 곧바로 0 을 돌려줘요. F5 로 실행하면 화면에 무엇이 보일까요? 콘솔 창은 뜰까요?

답 보기

아무것도 보이지 않아요. 하위 시스템이 Windows 라서 콘솔 창도 붙지 않고, Visual Studio 출력 창에 코드 0 으로 끝났다는 줄만 남아요. (3단계)

따라 하기

  1. 도구를 설치한다

    Visual Studio 설치 관리자에서 "C++를 사용한 게임 개발" 워크로드를 골라요. DirectX 11 헤더와 라이브러리가 들어 있는 Windows SDK 가 이 워크로드에 함께 들어와요. 예전 튜토리얼이 쓰던 DirectX SDK(June 2010)는 받지 않아요.

    원문과 비교

    원문도 같은 워크로드를 골라요. DirectX SDK 는 Windows SDK 로 대체되어 더 이상 받을 수 없다고 적고 있어요.

  2. 리포를 받고 프로젝트를 연다

    리포를 받아 이 편이 끝난 시점의 태그로 옮긴 다음 DxRenderDojo.sln 을 열어요. 프로젝트 설정은 리포에 들어 있어서 새로 만들 것이 없어요.

    원문과 비교

    원문은 "Windows 데스크톱 애플리케이션" 템플릿으로 새 프로젝트를 만들고, 템플릿이 만든 헤더·소스·리소스 파일을 지운 다음 플랫폼을 x64 로 바꿔요. 리포의 프로젝트 파일이 그 결과에 해당해요.

  3. 프로젝트 설정을 확인한다

    하위 시스템이 Windows 라서 이 프로그램은 main 대신 WinMain 에서 시작하고, 실행해도 콘솔 창이 붙지 않아요. 02편부터 창을 직접 만들기 때문에 쓰는 설정이에요.

    프로젝트 속성에서 아래 다섯 값을 확인해요. 리포의 프로젝트 파일에 이미 들어 있어서 고칠 곳은 없어요.

    • 플랫폼도구 모음의 솔루션 플랫폼 · x64. 원문도 행렬 같은 타입의 정렬 때문에 x64 로 빌드함
    • 문자 집합구성 속성 › 고급 · 유니코드
    • 언어 표준C/C++ › 언어 · /std:c++20
    • 추가 옵션C/C++ › 명령줄 · /utf-8. BOM 없이 저장한 소스를 UTF-8 로 읽게 함
    • 하위 시스템링커 › 시스템 · /SUBSYSTEM:WINDOWS

    스스로 설명해 보기

    /utf-8 을 빼도 지금의 Main.cpp 는 아무 문제 없이 빌드돼요. 왜 그럴까요? 어떤 코드를 넣으면 문제가 생길까요?

  4. 빌드하고 실행한다

    구성을 Debug · x64 로 두고 F5 로 실행해요. WinMain 이 곧바로 0 을 돌려주니 창 없이 끝나고, 출력 창에 코드 0 으로 종료했다는 줄이 남아요.

    줄 단위 풀이
    • int WINAPI WinMain 하위 시스템이 Windows 인 프로그램의 진입점. WINAPI 는 Windows 가 부르는 함수의 호출 규약
    • _In_ · _In_opt_ 코드 분석 도구가 읽는 표시(SAL). 컴파일 결과에는 영향이 없음
    • HINSTANCE Instance 실행 중인 exe 를 가리키는 핸들
    • HINSTANCE PrevInstance 16비트 Windows 시절의 흔적. 지금은 항상 nullptr
    • PSTR CmdLine 명령줄 문자열. 02편에서 wWinMain 으로 바꾸면 와이드 문자열(PWSTR)로 받음
    • int ShowCmd 창을 처음 어떻게 보일지(보통, 최소화 등). 02편에서 ShowWindow 에 넘김
    • return 0; 프로세스의 종료 코드

  5. macOS 에서 빌드하고 실행한다

    맥에서는 같은 코드를 mingw-w64 로 Windows 용 exe 로 빌드하고 Wine 으로 실행해요. Windows 만 쓴다면 이 단계는 건너뛰어요.

    Wine 은 Direct3D 11 을 Metal 로 옮겨 주는 D3DMetal 이 들어 있는 Game Porting Toolkit 을 써요. 설치가 끝나면 x86_64-w64-mingw32-g++ --version 으로 컴파일러가 잡히는지 확인해요.

    mac-build.sh 가 build-mac/DxRenderDojo.exe 를 만들고 mac-run.sh 가 그 exe 를 Wine 으로 실행해요. Windows 에서처럼 창 없이 곧바로 끝나면 정상이에요.

다 됐는지 확인

흔한 실수

직접 만든 프로젝트에서 한글 주석 바로 다음 줄이 빌드에서 빠짐. 경고는 C4819 하나뿐

원인/utf-8 이 없으면 MSVC 가 BOM 없는 소스를 한국어 Windows 의 코드 페이지(CP949)로 읽어요. 한글 주석이 홀수 글자로 끝나고 줄끝이 LF 면 마지막 바이트가 줄바꿈과 한 글자로 묶여, 주석이 다음 줄까지 이어져요. 에러 없이 빌드되고 PC 에 따라 증상이 갈려요.

해결C/C++ › 명령줄 › 추가 옵션에 /utf-8 을 넣어요. 이 리포는 /utf-8 에 더해 .gitattributes 로 C++ 소스의 줄끝을 CRLF 로 받게 해 두었어요.

본문3단계 : /utf-8 이 하는 일

콘솔 앱 템플릿으로 만든 프로젝트에 WinMain 을 쓰면 error LNK2019 : main 을 확인할 수 없음

원인하위 시스템이 콘솔이면 링커가 진입점으로 main 을 찾아요. 코드에는 WinMain 만 있어서 링크가 실패하고 LNK1120 이 뒤따라요.

해결링커 › 시스템 › 하위 시스템을 /SUBSYSTEM:WINDOWS 로 바꿔요.

본문3단계 : 하위 시스템과 진입점

macOS 에서 wine: command not found

원인Game Porting Toolkit 은 wine 이 아니라 wine64 명령을 설치해요.

해결./scripts/mac-run.sh 로 실행해요. 스크립트가 wine64 를 찾아서 써요.

CMake 와 macOS

CMakeLists.txt+16MSVC 와 mingw 공통 빌드 설정 
cmake_minimum_required(VERSION 3.25)
project(DxRenderDojo LANGUAGES CXX)

add_executable(DxRenderDojo WIN32 Source/Main.cpp)
target_compile_features(DxRenderDojo PRIVATE cxx_std_20)
target_compile_definitions(DxRenderDojo PRIVATE UNICODE _UNICODE)

if(MSVC)
	target_compile_options(DxRenderDojo PRIVATE /W3 /utf-8)
else()
	target_compile_options(DxRenderDojo PRIVATE -Wall)
endif()

if(MINGW)
	target_link_options(DxRenderDojo PRIVATE -static -static-libgcc -static-libstdc++)
endif()

#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."

CONFIG="${1:-Debug}"

cmake -B build-mac -G Ninja \
	-DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-mingw-x86_64.cmake \
	-DCMAKE_BUILD_TYPE="$CONFIG" \
	-DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build-mac

echo "빌드 완료 : build-mac/DxRenderDojo.exe ($CONFIG)"
scripts/mac-run.sh+15wine64 로 실행 
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."

EXE=build-mac/DxRenderDojo.exe
[ -f "$EXE" ] || { echo "$EXE 가 없습니다. scripts/mac-build.sh 로 먼저 빌드하세요."; exit 1; }

export WINEPREFIX="${WINEPREFIX:-$HOME/Library/Caches/DxRenderDojo/wineprefix}"
mkdir -p "$WINEPREFIX"
export WINEDEBUG="${WINEDEBUG:--all}"

WINE_BIN="$(command -v wine64 || command -v wine || true)"
[ -n "$WINE_BIN" ] || { echo "wine64 를 찾을 수 없습니다. Game Porting Toolkit 을 설치하세요."; exit 1; }

"$WINE_BIN" "$EXE"
