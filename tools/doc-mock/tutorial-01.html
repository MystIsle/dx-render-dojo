개발 환경 셋업

튜토리얼 코드를 쓰기 전에, 같은 빈 프로젝트가 Windows와 macOS 양쪽에서 빌드되는 상태를 만듭니다.

이 편 (1 / 61) 공통 진도 : 01~30, 41~45, 스키닝(α) 각자 선택

이 편을 마치면

  • WindowsVisual Studio에서 x64 Debug 빌드가 경고 없이 끝납니다
  • macOS같은 코드를 mingw-w64로 Windows용 .exe로 빌드하고, Wine으로 실행합니다
  • 공통이 리포에서 코드를 쓰기 전에 볼 규약 파일이 어디 있는지 압니다

원문과 다른 점

원문을 옆에 펴 놓고 따라온다면 이 표부터 보세요.
코드를 새로 쓰기 때문에 원문 그대로가 아닌 곳이 있습니다.

항목원문이 리포
IDEVisual Studio 2022Visual Studio 2022 이상
작성 PC는 Visual Studio 2026
프로젝트템플릿으로 새로 만들고 기본 파일을 지움리포에 들어 있는 프로젝트 파일을 엶
macOS다루지 않음CMake + mingw-w64로 빌드
Wine(Game Porting Toolkit)으로 실행
소스 인코딩다루지 않음BOM 없는 UTF-8
MSVC에는 /utf-8
코드 규약없음CODING_STYLE.md, clang-format, clang-tidy

따라 하기

  1. 도구 설치

    Visual Studio 설치 관리자에서 C++를 사용한 게임 개발 워크로드를 고릅니다.
    Windows SDK가 이 워크로드에 같이 들어옵니다.

    d3d11.h와 DirectXMath가 Windows SDK 안에 있어서, 예전 튜토리얼이 쓰던 DirectX SDK(June 2010)는 받지 않습니다.

    빌드 도구와 Wine을 Homebrew로 설치합니다.
    Wine은 D3D11을 Metal로 옮겨 주는 D3DMetal이 들어 있는 Game Porting Toolkit을 씁니다.

    설치가 끝나면 x86_64-w64-mingw32-g++ --version으로 컴파일러가 잡히는지 확인합니다.

  2. 리포 받기

    받은 리포에서 코드를 쓰기 전에 아래 세 파일을 한 번 열어 둡니다.

    • docs/CODING_STYLE.md이름 짓기, 소유, 에러 처리 규약
    • .clang-format중괄호·탭·120자 같은 서식을 맞춤
    • .clang-tidyFModel, bReady 같은 이름 규칙을 검사

  3. 프로젝트 설정 확인

    DxRenderDojo.sln을 열고, 프로젝트 속성에서 아래 다섯 값이 맞는지 봅니다.
    리포의 프로젝트 파일에 이미 들어 있으니 고칠 곳은 없어야 합니다.

    솔루션 플랫폼도구 모음
    x64
    문자 집합구성 속성 › 고급
    유니코드
    C++ 언어 표준C/C++ › 언어
    /std:c++20
    추가 옵션C/C++ › 명령줄
    /utf-8
    하위 시스템링커 › 시스템
    /SUBSYSTEM:WINDOWS
    원문은 왜 x64를 요구하나

    XMMATRIX는 SSE 명령으로 한 번에 계산하려고 16바이트 경계에 맞춰진 메모리를 기대합니다.

    64비트 Windows의 힙 할당은 기본이 16바이트 정렬이지만 32비트는 8바이트입니다.
    그래서 x86으로 빌드하면 XMMATRIX를 멤버로 가진 객체의 정렬이 어긋나, 행렬을 쓰기 시작하는 03편 이후에 크래시가 날 수 있습니다.

    macOS에서는 CMake가 cmake/toolchain-mingw-x86_64.cmake로 mingw-w64 컴파일러를 고릅니다.
    손댈 설정은 없습니다.

    /utf-8은 MSVC 전용 옵션이라 macOS 빌드에는 들어가지 않습니다.
    GCC는 소스를 기본으로 UTF-8로 읽습니다.

  4. 빌드하고 실행

    구성을 Debug · x64로 두고 F5로 실행합니다.
    창은 뜨지 않고 바로 끝나며, 출력 창에 코드 0으로 종료했다는 줄이 남으면 정상입니다.
    창은 02편에서 띄웁니다.

흔한 실수

03편 이후 XMMATRIX를 쓰는 곳에서 이유 없이 크래시가 난다

원인솔루션 플랫폼이 x86으로 남아 있습니다.
01편에서는 증상이 없어서 늦게 발견됩니다.

해결도구 모음에서 x64로 바꾸고 다시 빌드합니다.

경고 C4819 : 파일에 현재 코드 페이지(949)에서 표시할 수 없는 문자가 있다

원인/utf-8이 빠져서 MSVC가 BOM 없는 소스를 CP949로 읽었습니다.
한글 주석과 문자열이 깨집니다.

해결C/C++ › 명령줄 › 추가 옵션에 /utf-8을 넣습니다.

macOS에서 wine: command not found

원인Game Porting Toolkit은 wine이 아니라 wine64 명령을 설치합니다.

해결./scripts/mac-run.sh로 실행합니다.
스크립트가 wine64를 찾아서 씁니다.
